# Reproducir y desplegar la referencia AulaFlow 1.0.0

Esta copia genera el JAR `target/aulaflow-1.0.0.jar` y la imagen local `localhost/aulaflow:1.0.0`. La versión comunicada por el servidor es `1.0.0`. No necesitas una etiqueta de Git ni acceso al repositorio de origen.

Para un primer arranque utiliza la [guía para el alumnado](../alumnado/01-primer-arranque.md). Este procedimiento añade verificación operativa y despliegue en contenedores. Los comandos de `container/` utilizan Bash y Podman: ejecútalos en un entorno Linux, macOS preparado para Podman o una máquina Linux del laboratorio.

## 1. Obtener y verificar el proyecto

Descarga el ZIP de `main` o clona [JaumeLloret/aulaflow](https://github.com/JaumeLloret/aulaflow). Si tienes Git, `git rev-parse HEAD` permite registrar exactamente qué revisión estás comprobando. El ZIP no incluye historial de Git.

Comprueba Java 26 y Maven Wrapper, y ejecuta la suite:

```bash
java --version
./mvnw --version
./mvnw clean verify
```

En PowerShell utiliza `.\mvnw.cmd --version` y `.\mvnw.cmd clean verify`. No omitas pruebas. El resultado esperado es **BUILD SUCCESS** y el JAR indicado al principio.

En una copia con Git, comprueba además scripts y metadatos:

```bash
for script in container/*.sh; do bash -n "$script"; done
bash container/verify-release-metadata.sh
```

El verificador usa `git ls-files` para comprobar los archivos versionados; esa parte necesita un checkout Git y no se aplica al ZIP.

## 2. Ejecutar el JAR

Define tu usuario y contraseña para el primer arranque siguiendo la guía del alumnado. Ejecuta desde la carpeta del proyecto:

```bash
java -jar target/aulaflow-1.0.0.jar
```

Comprueba la portada, el login y **http://127.0.0.1:8080/api/v1/health**. El JSON de salud debe indicar `status: UP` y `version: 1.0.0`.

## 3. Construir la imagen y preparar los datos

Detén la ejecución local para liberar el puerto. Comprueba `podman --version` y que dispones de un proveedor Compose compatible. Después:

```bash
bash container/build-image.sh
bash container/create-volume.sh
```

El primer comando verifica el proyecto y construye la imagen. El segundo prepara `aulaflow-data`, un volumen externo. El contenedor se ejecuta con UID/GID 10001 y la base está en `/var/lib/aulaflow/aulaflow.db`.

La base del volumen es independiente de `data/aulaflow.db` en tu ordenador. Si está vacía, define las variables de administrador en la terminal de Compose. No guardes credenciales en archivos versionados.

## 4. Arrancar y comprobar el contenedor

```bash
podman compose up -d
podman compose ps
curl -i http://127.0.0.1:8080/api/v1/health
```

La publicación predeterminada es solo `127.0.0.1:8080`. La [guía de Podman](../deployment/2.1-local-podman-compose.md) detalla variables, permisos y diagnóstico del healthcheck.

Recorre la aplicación:

1. Inicia sesión y crea un tablero.
2. Crea, edita y mueve una tarjeta.
3. Asigna una etiqueta y marca un elemento de su lista.
4. Exporta CSV y comprueba la previsualización de importación.
5. Detén con `podman compose down` y arranca otra vez.
6. Inicia sesión y comprueba que los datos y su orden se conservan.

Las sesiones se pierden al reiniciar; los datos del volumen permanecen. Una vez creada la cuenta puedes retirar las variables iniciales. Cambiarlas no cambia su contraseña.

## 5. Backup y restauración

Con el servicio funcionando:

```bash
bash container/backup.sh
```

La copia se guarda en `aulaflow-backups` y se valida antes de aceptarse. Para restaurar, detén primero el servicio y utiliza el nombre real de una copia que hayas creado:

```bash
podman compose down
bash container/restore.sh aulaflow-YYYYMMDDTHHmmssSSSZ.db
podman compose up -d
```

Consulta el [procedimiento completo de backup y restore](../deployment/2.2-backup-restore-security.md) antes de restaurar datos que quieras conservar. El script rechaza restauraciones con el volumen activo y valida el archivo antes de sustituir la base.

## 6. Registrar lo comprobado

Anota la revisión del código, el JDK, el resultado de Maven y el recorrido realizado en tu entorno. Las pruebas automatizadas no sustituyen comprobar navegador, permisos y almacenamiento de una instalación concreta.

Para detener sin borrar datos utiliza `podman compose down`. Conserva el volumen de datos y las copias. HTTPS de producción, colaboración multiusuario y recuperación de contraseñas desde la interfaz quedan fuera de esta referencia.
